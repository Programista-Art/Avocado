#### Kluczowe zmiany
1. **Poprawka: Odłączanie zagnieżdżonych instrukcji Else.**

 Framework. AvoRender składa się z dwóch głównych warstw:
    1. Języka skryptowego AvoRender, który jest w locie transpilowany do czystego JavaScriptu (przeznaczony do budowy UI).
    2. Wewnętrznego API napisanego w Avocado, służącego do kompilacji, budowania wirtualnego drzewa DOM oraz generowania końcowego kodu HTML i JS.
Poniżej znajdziesz kompleksowe zestawienie dostępnych funkcji oraz wspieranych struktur językowych.

1. Funkcje i składnia języka skryptowego Avocado
Język Avocado używa intuicyjnej, polskojęzycznej składni. Po przetworzeniu przez wewnętrzny parser i generator kodu, skrypty są transpilowane na nowoczesny JavaScript. Wszystkie wygenerowane instrukcje Avocado automatycznie zamykane są w nasłuchiwaczu zdarzeń DOMContentLoaded, by bezpiecznie manipulować dokumentem po jego wczytaniu.
    • Deklaracja zmiennych (zmienna) Pozwala na definiowanie zmiennych. Kompilator Avocado automatycznie tłumaczy to słowo kluczowe na instrukcję let z języka JavaScript. Przykład użycia:
zmienna powitanie = 'Witaj w AvocadoWeb!'; 
Tworzenie elementów (dokument.stworz_element) Podstawowa funkcja do budowania nowych węzłów DOM. Jest transpilowana bezpośrednio do metody document.createElement(...). Przykład użycia: 
zmienna panel = dokument.stworz_element('div'); zmienna przycisk = dokument.stworz_element('button'); 
Modyfikacja wyglądu w czasie rzeczywistym (ustaw_styl) Funkcja odpowiadająca za ustawianie właściwości CSS dla wskazanych komponentów. Przyjmuje jako argumenty element oraz łańcuch znaków. Transpilator zamienia to wywołanie na dodanie reguł CSS do właściwości element.style.cssText += .... Przykład użycia: 
ustaw_styl(panel, 'background-color: #333; padding: 20px;'); ustaw_styl(przycisk, 'color: green; border-radius: 5px;'); 

Manipulacja strukturą DOM (dodaj_dziecko) Służy do zagnieżdżania jednych elementów wewnątrz drugich. Odpowiednik javascriptowego appendChild. Avocado wspiera również bezpośrednie przypięcie węzła do struktury głównej poprzez dokument.body. Przykład użycia: 
panel.dodaj_dziecko(przycisk); 
dokument.body.dodaj_dziecko(panel); 

Funkcje frameworka AvoRender
Jako programista środowiska Avocado IDE masz dostęp do potężnych narzędzi kompilacji (tworzenie tzw. Abstraktcyjnych Drzew Składniowych - AST) i generowania czystego HTMLa.
Moduł avo_core – Sądzenie skryptów (Transpilator)
    • compile_avocado_to_js(const source: string): string Główny punkt wejścia frameworka. Przyjmuje kod źródłowy w języku Avocado, parsuje go w struktury AST i zwraca gotowy kod JavaScript. Przykład użycia (Pascal):
tekst  js_code
początek 
js_code = compile_avocado_to_js('zmienna div = dokument.stworz_element(''div'');'); 
koniec 
Moduł avo_dom – Wirtualne Drzewo Dokumentu (DOM)
Służy do programowego budowania struktury HTML po stronie backendu, zanim strona trafi do przeglądarki klienta.
    • dom_create_element(const tag_name: string): pdom_node_t Tworzy w pamięci serwera nowy węzeł odpowiadający danemu tagowi HTML.
    • dom_create_text_node(const text: string): pdom_node_t Tworzy prosty węzeł tekstowy, który można wstawić wewnątrz innych elementów.
    • dom_set_id(node: pdom_node_t; const id: string) Przypisuje identyfikator (atrybut id) elementowi HTML.
    • dom_add_class(node: pdom_node_t; const class_name: string) Dodaje wskazaną klasę CSS, poprawnie doklejając ją do już istniejących klas węzła (oddzielając spacją).
    • dom_set_style(node: pdom_node_t; const style_string: string) Rozszerza definicje CSS przypisane do właściwości style serwerowego węzła.
    • dom_append_child(parent, child: pdom_node_t) Umieszcza element child jako dziecko wewnątrz elementu parent, tworząc relacyjną strukturę interfejsu.
    • dom_to_html(node: pdom_node_t): string Funkcja, która rekurencyjnie konwertuje całe wygenerowane przez Ciebie wirtualne drzewo DOM do czystego kodu HTML (string), włącznie ze wszystkimi zagnieżdżeniami.

  pdom_node_t  kontener, tekst
  tekst wynikowy_html

Generowanie drzewa DOM po stronie Avocado (backend) za pomocą modułu avo_dom jest całkowicie opcjonalne. Framework AvoRender został zaprojektowany w sposób modułowy, co oznacza, że jego dwie główne części są od siebie niezależne:
    1. Transpilator (Frontend) – kompiluje język Avocado do JavaScriptu.
    2. Wirtualny DOM (Backend) – służy do programowego generowania statycznego HTML po stronie serwera.
Jeśli zależy Ci tylko na tym, aby użyć języka skryptowego Avocado do wygenerowania logiki JavaScript (i podpięcia jej pod zwykły, pusty plik HTML), w ogóle nie musisz używać modułów avo_dom ani avo_types. Wystarczy sam rdzeń frameworka – avo_core.

Zarządzanie czasem (Timery / Interwały)
Obecnie kod wykonuje się od razu (lub czeka na zdarzenie/sieć). W grach, animacjach czy aplikacjach czatowych (gdzie np. chcemy odpytywać serwer co 5 sekund) potrzebujemy czasu.
    • Proponowane komendy: * za_czas(1000, funkcja() ... ) -> transpilowane do setTimeout.
        ◦ wykonuj_co(5000, funkcja() ... ) -> transpilowane do setInterval.
    • Przykład w AvoRenderze:
wykonuj_co(2000, funkcja()
poczatek
    pobierz_z_sieci("http://localhost:8080/api/nowe_wiadomosci", funkcja(dane) ... );
koniec);
Wyszukiwanie elementów w drzewie (Query Selectors)
Teraz, aby zmienić tekst w elemencie, musisz trzymać go w zmiennej (np. zmienna moj_div = stworz_element('div')). Przy dużych aplikacjach to bywa uciążliwe. Dodanie selektorów pozwoli Ci "znaleźć" element gdziekolwiek w kodzie.
    • Proponowana komenda: wyszukaj_element("#id_elementu") -> transpilowane do document.querySelector(...).
    • Przykład w AvoRenderze:
zmienna ukryty_panel = wyszukaj_element("#panel-boczny");
ustaw_styl(ukryty_panel, "display: block;");

Pamięć podręczna przeglądarki (Local Storage)
Wyobraź sobie, że użytkownik wybiera "Ciemny motyw" w Twojej aplikacji. Jeśli zamknie okno i otworzy je ponownie, ustawienie zniknie. Przeglądarki mają wbudowaną bazę danych, do której AvoRender powinien mieć dostęp.
    • Proponowane komendy: * zapisz_lokalnie("klucz", "wartość") -> localStorage.setItem(...)
        ◦ czytaj_lokalnie("klucz") -> localStorage.getItem(...)
    • Przykład w AvoRenderze:
zmienna ostatni_login = czytaj_lokalnie("nazwa_usera");
jesli (ostatni_login != "")
poczatek
    ustaw_tekst(powitanie, "Witaj ponownie " + ostatni_login);
koniec
System Importów (Modułowość Plików)
Jeśli zaczniesz pisać aplikację na 2000 linijek, plik widok.avo stanie się nieczytelny. Prawdziwe frameworki pozwalają dzielić kod na mniejsze pliki. To mechanizm, który wdrożyłbyś po stronie Pascala (Avoraisera). Zanim parser zacznie czytać kod, sprawdza, czy są w nim słowa importuj. Jeśli tak, "wkleja" w to miejsce zawartość innego pliku.
      Proponowana komenda: importuj "komponenty/przycisk.avo";
Reaktywność (State Management) - Poziom Hardcore
To jest to, co sprawiło, że React zdominował rynek. Obecnie w AvoRenderze musisz robić wszystko "ręcznie" (imperatywnie): czyli pobrać wartość, znaleźć element, ustawić nową wartość. W systemie reaktywnym "wiążesz" zmienną z elementem wizualnym. Jeśli wartość zmiennej się zmieni w tle, ekran aktualizuje się magicznie sam.
      Proponowana komenda: powiaz_stan(element, zmienna_stanu);

Zabezpieczenie Backendu (Twój kod w Pascalu)
Musimy uodpornić serwer AvocadoNet na ataki typu "ściana tekstu" (przepełnienie bufora/RAMu). Jeśli ładunek (zapytanie) będzie miał więcej niż 1000 znaków, serwer odrzuci go ze statusem 413 Payload Too Large.
Znajdź w swoim serwerze (w procedurze ObslugaZadania) warunek else if Req.Path = '/api/czat/pisz' then i zmodyfikuj go następująco:
else if Req.Path = '/api/czat/pisz' then
  begin
    // ZABEZPIECZENIE: Blokada zbyt długich wiadomości (atak DoS / Spam)
    if Length(Req.Body) > 1000 then
    begin
      Res.StatusCode := 413; // Kod HTTP: Ładunek zbyt duży
      Res.Body := '{"blad": "Wiadomość jest za długa! Maksymalna długość to 1000 znaków."}';
      Exit; // Przerwij działanie funkcji, nie zapisuj do bazy!
    end;

    // Odbieramy nową wiadomość POST (tutaj reszta Twojego dotychczasowego kodu)
    Res.StatusCode := 200;
    
    if BazaCzatu = '[]' then
      BazaCzatu := '[' + Req.Body + ']'
    else
    begin
      Delete(BazaCzatu, Length(BazaCzatu), 1);
      BazaCzatu := BazaCzatu + ',' + Req.Body + ']';
    end;
    
    Res.Body := '{"status": "Wiadomość zapisana!"}';
  end


To PR wprowadza niezbędny mechanizm bezpieczeństwa dla formatowania danych dostarczanych przez użytkownika w skryptach AvoRender!

Poprzez opakowanie danych użytkownika w nowy wrapper proceduralny `bezpieczny_tekst`:

zmienna dane = bezpieczny_tekst(pobrany_input);


Transpilator wygeneruje funkcję rzutowania inline i zamiany opartą na wyrażeniach regularnych:

let dane = String(pobrany_input).replace(/\\/g, "\\\\").replace(/"/g, "\\\"");


Zapobiega to uszkodzeniu dowolnego formatowania inline JSON lub zagnieżdżonej konkatenacji ciągów znaków przez złośliwe ukośniki odwrotne lub cudzysłowy wstrzykiwane do pól użytkownika przed wysłaniem danych za pomocą procedur `wyslij_do_sieci` lub `wyslij_sygnal`.
